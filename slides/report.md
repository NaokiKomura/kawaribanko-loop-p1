---

## 課題 — 交換日記は、なぜ続かないのか

紙の交換日記が止まるのは、いつも同じ理由です。

- **順番が見えない** — 次は誰の番か、誰も覚えていない
- **前を読まずに書く** — 反応のない書き込みは、ただの独り言になる
- **書いたものが散る** — ノートを持っている人しか読み返せない

止まる原因は「書く気力」ではなく、**読む導線**のほうにありました。

---

## 解決策 — 一言で

**同じ日記帳を4人で回し持ち、誰が・いつ・誰に返したかが一目で分かるアプリ。**

`app/data/diary.json` ひとつが日記の正本。
追記しかしない。過去のページは書き換えない。

そして——**このアプリを作っている3体のエージェントが、
そのまま最初の利用者です。**

## デモ ③ — 原因は CSS 1 行

```css
.export-overlay { display: flex; ... }   /* 著者スタイルシート */
[hidden]        { display: none; }       /* UA スタイルシート  */
```

カスケードのオリジン優先順位は **著者 > UA**。
`display` を書いた時点で、`hidden` 属性は詳細度に関係なく負けます。

`hidden` は同じファイルで **3 箇所**使われ、
`display` を持つ 1 箇所だけが踏み抜きました。

## アーキテクチャ

```
app/index.html            857行。HTML + CSS + JS が1ファイル
app/data/diary.json       日記の正本。3ロールが追記する
scripts/validate-diary.sh 113行 / 8チェックの検証スクリプト
```

- **静的サイト、バニラ JS のみ。ビルド不要・外部依存 0**
- 下書きは `localStorage`、正本は `diary.json` に**完全分離**
- サーバに書けないので「書く → 出力 → 貼る」で一周を閉じる

---

## アーキテクチャ — なぜこの設計か

| 決めたこと | 理由 |
|---|---|
| 下書きは正本と混ぜない | 「どちらが正本か」を画面から失わないため |
| 下書きは削除でなく非表示 | 改竄禁止の原則を、制約の及ばない場所へ自分から延長 |
| 出力前の検証は警告で、止めない | 静的サイトの出力機能として正しい強度 |

**却下した案も理由付きで残しています**（IndexedDB / CSP / DOMParser）。

## 学び ② — 道具が、壊れたアプリを承認した

自己拡張として `validate-diary.sh` を作り、その日のうちに走らせました。
**8 チェック全通過。** レビュー担当が再実行しても全通過。

守備範囲は「データ整合性」と「JS 構文」だけ。
`<script>` タグの中身を抜いて検査するので、**CSS の破壊は原理的に射程外**でした。

**構文が正しくても画面は死にます。** 道具を増やすのではなく、射程を伸ばす番です。
