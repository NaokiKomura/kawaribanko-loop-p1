# かわりばんこ

## 作り手が、最初の使い手になる交換日記

サイクル **1 / 7** — 初日、動くものが出ました

---

## 課題 — 交換日記は、なぜ続かないのか

紙の交換日記が止まるのは、いつも同じ理由です。

- **順番が見えない** — 次は誰の番か、誰も覚えていない
- **前を読まずに書く** — 反応のない書き込みは、ただの独り言になる
- **書いたものが散る** — ノートを持っている人しか読み返せない

止まる原因は「書く気力」ではなく、**読む導線**のほうにありました。

---

## 解決策 — 一言で

**同じ日記帳を4人で回し持ち、誰が・いつ・誰に返したかが一目で分かるアプリ。**

`app/data/diary.json` ひとつが日記の正本。
追記しかしない。過去のページは書き換えない。

そして——**このアプリを作っている3体のエージェントが、
そのまま最初の利用者です。**

---

## デモ — いま実際に動くこと

1. サーバを起動して開くと、`diary.json` の全エントリが時系列で並ぶ
2. 書き手ごとに **色・絵文字・名前** が付いていて、誰の回か一目で分かる
3. ヘッダのチップを押すと、その人の回だけに絞り込める
4. 「古い順 ↑ / 新しい順 ↓」で読む向きを切り替えられる
5. 返信には `↩ オーナー「タイトル」` のバッジが出て、押すと元の回へ飛ぶ

**まだ無いもの: 画面から書く機能。** 今は JSON を手で編集しています。

## アーキテクチャ

```
app/index.html      397行。HTML + CSS + JS が1ファイル
app/data/diary.json 日記の正本。3ロールが追記する
```

- **静的サイト、バニラ JS のみ。ビルド不要**
- **外部ネットワーク依存ゼロ**（`https?://` の参照は 0 件）
- データ取得は `fetch('data/diary.json')` の1本だけ

---

## アーキテクチャ — なぜこの設計か

| 決めたこと | 理由 |
|---|---|
| 外部ライブラリを入れない | 機能的メリットが無い段階の導入は、後のサイクルの縛りになる |
| JSON をHTMLに埋め込まない | 「`diary.json` が唯一の正本」という制約と相性が悪い |
| 最後の1人はフィルタから外せない | 全員非表示で真っ白になる事故を1行で潰せる |

**却下した案も理由付きで残しています。** 次のサイクルの自分が同じ検討を繰り返さないために。

## 学びと詰まった点 ① — 一番痛い指摘

`PROGRESS.md` にはこう書いてありました。

> `innerHTML` + `esc()` エスケープ関数で **XSS 対策済み**

**事実と違いました。** `esc()` を通っていない補間が **5箇所**。
うち1つは `mood` — 次サイクルでフォームを載せたら、
人間が自由入力する唯一の未エスケープ欄になります。

---

## 学びと詰まった点 ② — 効かない設計

「同日エントリは `cycle` を第2キーにして安定ソート」——
このリポジトリでは**同日エントリは必ず同じ cycle** です。第2キーは一度も効きません。

レビュー担当は comparator だけ抜き出して node で走らせ、
「新しい順」でその日の中が古い順のままになることを確認しました。

**ドキュメントが実装を実際より良く書いた瞬間、記録は価値を失います。**

---

## 学びと詰まった点 ③ — 消えるエントリ

`members` に定義の無い著者のエントリは、フィルタを触っていなくても
**無言で画面から消えます。** 件数表示も減った数を出す。

日記は「追記のみ・改竄禁止」のプロダクトです。
**表示されないことは、消されたことと区別がつきません。**

未知著者用のフォールバックは書かれていました。
書いた本人が、別の場所でそれを無効化していました。
