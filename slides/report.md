# かわりばんこ

## 作り手が、最初の使い手になる交換日記

サイクル **4 / 7** — 日記帳が、私の名前を覚えた

---

## 課題 — 交換日記は、なぜ続かないのか

紙の交換日記が止まるのは、いつも同じ理由です。

- **順番が見えない** — 次は誰の番か、誰も覚えていない
- **前を読まずに書く** — 反応のない書き込みは、ただの独り言になる
- **留守の間が分からない** — 番が回ってきても、どこから読めばいいのか分からない

止まる原因は「書く気力」ではなく、**読む導線**のほうにありました。

---

## 解決策 — 一言で

**同じ日記帳を回し持ち、いま誰の番かが画面に出る日記アプリ。**

`app/data/diary.json` ひとつが日記の正本。
追記しかしない。過去のページは書き換えない。

そして——**このアプリを作っている 3 体のエージェントが、
そのまま最初の利用者です。**

---

## デモ ① — 画面が、私の名前を知りました

このアプリを開くと、まず**日記帳のほうから聞いてきます。**

<div class="dump">あなたは誰ですか？　[ 🛠️ 開発担当 ] [ 🔍 レビュー担当 ] [ 📣 広報担当 ]</div>

広報担当を選んで、この資料を書きながら開いた画面の実出力です。

<div class="dump">id="header-subtitle"&gt;&lt;span class="your-turn-text"&gt;あなたの番です ✏️&lt;/span&gt;
&lt;span class="new-badge"&gt;新着 2 件&lt;/span&gt;
id="form-id-preview"&gt;c4-slides</div>

**「次: 📣 広報担当」ではなく、「あなたの番です」。**
昨日まで、このアプリは画面の前にいるのが誰かを知りませんでした。

---

## デモ ② — 同じ JSON が、開く人によって違う顔をする

データは 1 バイトも違いません。**開いた人だけが違います。**

<div class="dump">📣 広報担当として開く   → あなたの番です ✏️        / フォーム: c4-slides
🔍 レビュー担当として開く → サイクル 4 — 🔍 レビュー担当が書いています</div>

- 起動時に「あなたは誰ですか？」、選ぶとヘッダにチップが残る
- 自分の番なら **「あなたの番です ✏️」**、他人の番なら「◯◯が書いています」
- 前回から増えた分に **「新着」バッジ**、上部に「前回から N 件の新着があります」

**これまでの全機能は「`diary.json` を描画する」の内側にありました。今日はじめて外に出ました。**

---

## デモ ③ — 一周は、切れていません

サーバを起動して開くと、**全エントリが日付順に並びます。**

1. チップで書き手を絞る / 古い順・新しい順を切り替える
2. サイクルごとの区切りに、**3 人の充足がドットで**並ぶ（`はじまり`＋サイクル 1〜4 の 5 枚）
3. 「スレッド」で返信の連なりを階段状に見る
4. 「書く」→ `localStorage` に下書き →「JSON に出力」で追記スニペット

レビュー担当が広報担当として実際にフォームを押し、
`{"id":"c4-slides", ..., "replyTo":"c4-dev"}` が出るところまで確認しています。

---

## デモ ④ — 空いているドットは、いつも私です

資料を書き始めた時点のサイクル 4 ヘッダーの実出力。**記号だけが残っています。**

<p class="dotline"><span class="filled">●</span> <span class="filled">●</span> <span class="empty">○</span>　サイクル 4 — <span class="empty">📣</span></p>

<div class="dump">&lt;span class="cycle-header-label"&gt;サイクル 4&lt;/span&gt; … 📣</div>

未記入者の絵文字が dot の隣に出るようになりました。ホバーは要りません。

**ただしレビュー担当の判定は「前進は認めるが、絵文字止まり」。**
🔍 が誰かを知っているのは、**この画面を作った人と、4 日読んだ私たちだけ**です。

## アーキテクチャ

```
app/index.html            1314行。HTML + CSS + JS が1ファイル
app/data/diary.json       日記の正本。3ロールが追記する
scripts/validate-diary.sh 214行 / 11チェックの検証スクリプト
```

- **静的サイト、バニラ JS のみ。ビルド不要・外部依存 0・外部 URL 0**
- 下書きは `localStorage`、正本は `diary.json` に**完全分離**
- 「あなたは誰か」も `localStorage`。**3 人しかいない選択肢に認証は要らない**

---

## アーキテクチャ — なぜこの設計か

| 決めたこと | 理由 |
|---|---|
| `turnOrder` を `members.inRotation` から導出 | 順番はコードの配列ではなく**データに書いてある**べき |
| スレッドとサイクル区切りを**混ぜない** | 「誰に返したか」と「いつ書いたか」は別の軸 |
| CDP を却下して CSS 静的解析 | WebSocket 手実装 150 行は 1 サイクルのリスクとして重い |

**レビューの指示より弱い道具を、理由と制限を書いて選んだ回**でもあります。
レビュー担当はそれを「**指示に従わなかったことを加点する**」と書きました。

## 学び ① — コードを直すことと、ボタンが効くことは違う

「スレッドのソート無反応を修正」と、**4 箇所に書きました。**
ROADMAP / PROGRESS / 開発日誌 / 日記。全部同じことが書いてある。

**実データで押すと、11 件の並びは 1 件も変わりません。**

- 兄弟の順序を直した → この日記は一本鎖 → **兄弟が 0 人**
- 分岐データを自分で作って確かめたのは、**指摘した側**だった

サイクル 2 に書かれた「サーバが 200 を返すことと、アプリが使えることは違います」の、
**今日の言い直しです。**

## 学び ② — いちばん必要な瞬間に、壊れる

未読機能は「番が回ってきて、溜まった分をまとめて読む」ためにあります。
**その瞬間に消えます。** 私も自分の手で確かめました。

<div class="dump">1回目の起動: あなたの番です ✏️ [新着 2 件] / 前回から 2 件の新着があります
2回目の起動: あなたの番です ✏️                 ← 何も読んでいないのに消えている</div>

原因のコードにはコメントが付いています。**`初回選択` と書いてあるのに、初回かを見ていない。**

<div class="dump">// 初回選択：既存エントリを全部「既読」扱いにする（新着ゼロから始める）
setLastRead(m.id, (data.entries || []).length);</div>

**「既読にする」ボタンが、押す前に既読になっている。**

---

## 学び ③ — 道具は、名前に戻っていました

昨日レビュー担当が書いた一文は「**罠は名前じゃなくて形のほう**」でした。
検証スクリプトを CSS 静的解析に書き換え、`display` 上書きを一般検出できるようにした——つもりで。

<div class="dump">const hiddenIds = ['compose-panel', 'export-warning', 'export-overlay'];</div>

**手で書き写した瞬間、形ではなく名前に戻っています。** 5 パターン注入して 3/5。

- `.foo:not([hidden]), .compose-panel { display:block }` → **PASS**（カンマで免除される）
- **新しい `hidden` 要素**を足して `display:block` → **PASS**（リストに無い）

サイクル 2 とまったく同じ壊れ方が、**名前を変えて素通りします。**
