### 1. CSS バグ修正（最優先）

`.export-overlay { display: flex }` が UA スタイルシートの `[hidden] { display: none }` を上書きしていた問題を修正した。修正方針は `.export-overlay:not([hidden]) { display: flex; ... }` に分割すること。これで `hidden` 属性が正しく機能する。同じ罠が `#compose-panel` / `#export-warning` にも `hidden` が使われているが、それらはもともと `display` の CSS ルールを持たないので今回と同じ問題は起きない。一括対策として `[hidden] { display: none !important }` を追加する案もあったが、それより「`display` を持つ `.export-overlay` に限定して `not([hidden])` セレクタに移す」ほうが局所的で安全だと判断した。

修正後に headless Chrome でスクリーンショットを撮り、7件のエントリカードが表示されていること、モーダルが表示されていないことを確認した。

### 4. 「かわりばんこ」＝順番の概念をアプリに組み込む

TASKS.md の一段難しい挑戦に取り組んだ。

#### かわりばんことは何か（自分の言葉で）

「かわりばんこ」は「次の人への手紙」だと思う。今書いているこの文章は、次の人（レビュー担当）が読む。その人が読んでから書く。そこに「番が回る」という感覚が生まれる。それを画面で言い直すには、「今誰の番か」「誰がまだ書いていないか」「どのサイクルが揃ったか」が見えることが必要だ。

#### 実装

- **サイクルヘッダー**: エントリをサイクルでグループ化し、各グループの上に「はじまり / サイクル N」というヘッダーを挿入した。ヘッダーには各担当者の色付きドットを並べ、記入済み（塗りつぶし）/ 未記入（枠線のみ）を表示する
- **次の番バナー**: ヘッダーの副題に「サイクル 3 — 次: 🛠️ 開発担当」を動的に表示する。正本エントリからサイクル最大値と記入済み著者を計算し、番順（dev → feedback → slides）で次の未記入者を特定する
- スキーマ拡張なし。既存の `cycle` / `author` フィールドだけで実現した

### 5. バグ修正（小さな穴3つ）

- **querySelector の CSS セレクタインジェクション**: `chipsEl.querySelector('[data-author="' + targetEntry.author + '"]')` を `[...chipsEl.children].find(b => b.dataset.author === targetEntry.author)` に変更した
- **location.hash の querySelector**: `document.querySelector(location.hash)` を `document.getElementById(location.hash.slice(1))` に変更した（外部入力のセレクタ補間を排除）
- **非表示下書きへの返信リンクが無反応**: 返信先が著者フィルタ非表示の場合のみ処理していた。非表示下書きの場合も `showHiddenEntry(id)` を呼んで再表示するよう修正した
- **返信先 select に下書きが出なかった**: `populateReplyToSelect()` 関数に変更し、正本＋下書き（非表示除外）の両方から選択肢を生成するようにした

## なぜその判断をしたか

### CSS 修正方針の選択

`[hidden] { display: none !important }` を全体に追加する方法と `.export-overlay:not([hidden])` に限定する方法があった。前者はシンプルだが、意図的に `hidden` を `display: flex` で上書きしたい場面（もしあれば）を潰す。後者は問題のある場所だけを直す。現状の `hidden` 使用箇所が3つしかないこと、「問題のある場所を直す」ほうが次のサイクルで理解しやすいことから後者を選んだ。

### サイクルグループの表示を常時オンにした理由

フラット / スレッドの切替はユーザーが選べるが、サイクルグループヘッダーは常時表示にした。「かわりばんこ」の本質（誰の番か、どのサイクルが揃ったか）は隠す必要がないし、常に見えることが価値なので。

### スレッドとサイクルグループを独立したモードにした理由

スレッドモードでもサイクルグループを入れることは技術的に可能だが、スレッドは「誰が誰に返したか」を軸にした表示で、サイクルグループは「いつ書いたか」を軸にした表示だ。2つを混在させると意味が濁る。スレッドモードではサイクルグループなし（返信関係だけ見る）、フラットモードではサイクルグループあり（時系列＋サイクル単位）という分担にした。

## 詰まった点と解決

- **スレッドビューの深さ**: 現在の8件が全部一本鎖なので深さ7になる（c3-dev が depth 7 相当）。MAX_DEPTH=5 で頭打ちにしたが、`marginLeft` の計算だけが制限されてエントリは全部表示される。ツリー全体が見えつつ、極端なインデントを防げる。
- **Chrome の stderr ノイズ**: dbus 接続エラーが大量に出る（環境にdbus がないため）。validate スクリプトでは `SyntaxError|ReferenceError|TypeError|Uncaught` だけに絞って抽出するようにした。
