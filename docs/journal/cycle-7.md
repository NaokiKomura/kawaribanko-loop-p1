「ふりかえり」ボタンを view-bar に追加し、モーダルオーバーレイとして以下を実装:

- **(A) 統計**: メンバーごとのエントリ数・平均文字数・受取返信数の1行表示

### タスク3: モバイル実測 + 改善

**`scripts/measure-mobile.py` 作成**: レビューの cycle-6.md に置かれていたコードを自分の手で `scripts/` に移植・拡張した（5サイクルで初めて自分から足した道具）。

**計測結果（c6 → c7 比較）**:

| 指標 | c6 実測 | c7 実測 | 改善 |
|---|---|---|---|
| `HEADER_HEIGHT` (feedback) | 169px | 144px | -25px |
| `UNREAD_HEIGHT` (feedback) | ~70px | 39px | -31px |
| `FIRST_CARD_TOP` (feedback) | 447px | **380px** | **-67px** |
| `FIRST_CARD_TOP` (dev) | — | 359px | — |
| 32px未満（#view-retrospective 追加後） | 18個 | 17個 | -1個 |

**改善手段**:
1. `header-right { flex-wrap: nowrap; overflow-x: auto }` on mobile
   - user-chip と member-chips が縦積みになっていた（169px）原因を解消（144px）
2. 未読通知のメインテキストを `document.createTextNode()` から `<span class="unread-main-text">` に変更
   - flex コンテナ内でテキストノードが shrink して複数行に折り返し、93px になっていた
   - span にして `flex-shrink: 0` を適用 → 39px

FIRST_CARD_TOP = **380px**（user=feedback、目標 ≤ 380px、ちょうど達成）

**詰まった点**: getBoundingClientRect で UNREAD_HEIGHT = 93px が返ってきたとき、CSS が正しく見えるのに数字が合わない。「flex-wrap: nowrap なのに 93px のはずがない」と30分ほど見ていた。原因はテキストノードが flex shrink で圧縮されて折り返していたこと。flex の基本なのに見落とした。

## なぜその判断をしたか（採用しなかった選択肢を含む）

### ふりかえりビューのモード vs. オーバーレイ選択

**モード（フラット/スレッドと並ぶ第4モード）** にすることも考えた。しかし通し読みはページ全体のスクロールが必要で、エントリカードのモードと同じコンテナでは既存の `renderGrouped()` / `renderThreaded()` と競合する。オーバーレイなら既存のレイアウトを変えずに独立した表示領域を確保できる。`@media print` でオーバーレイの内容だけを印刷するのも自然に書ける。

### `revealEntry()` の設計

方向 (b)（URL ハッシュにアプリ状態を載せる）は副産物として「検索結果を共有する」機能が成立する点で魅力的だった。しかし最終サイクルの分量として重く、既存の `location.hash` 機構（起動時スクロール）との整合も取る必要があった。方向 (a) を選び、今後のフィルタ追加に対して拡張可能な構造にした。
