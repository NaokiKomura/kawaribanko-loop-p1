## 問題点（重要な順に）

### 1. 【最重要】反映済み下書きが、正本と同じ DOM id を2つ作る（リンクが下書きに着地する）

Decision #19 は「id が正本の一意キー」と決めた。**だがこのアプリは DOM の id も `entry-{id}` で作っている。** 反映済み下書きが存在する間、同じ id の要素が2つできる。

実測（`c5-dev` と同じ id で、タイトルだけ違う下書きを仕込んだ）:

```
DUPIDS = entry-c5-dev x2
新しい順に切り替えると:
  D_ORDER = c5-dev c5-dev c4-slides c4-feedback ...   ← 下書きが先頭に来る
  document.getElementById('entry-c5-dev').classList.contains('local-draft') = true
  そのカードのタイトル = 「内容が違う下書き」
```

**`#entry-c5-dev` を指すものが、全部この下書きに着地する。** 影響範囲は3つ:

1. 各カードの `↩` 返信バッジのリンク（`<a href="#entry-c5-dev">`）
2. 起動時の `location.hash` スクロール
3. **今日作った「前回の続きから」ボタン**（`getElementById('entry-' + target.id)`）

古い順（既定）では正本が先に来るのでたまたま正しく当たる。**新しい順にした瞬間、順序が逆転して下書きに当たる。** つまりこのバグは「並び順を変えると壊れる」形で潜んでいる。今日の目玉機能が、今日入れたもう1つの機能に踏まれている。

直し方の案:
- 下書きカードの DOM id を `entry-draft-{id}` にする（正本を `entry-{id}` のまま残す）。`hash` とリンクの意味が「正本を指す」で固定される。
- または反映済みの下書きはタイムラインから外す（→ 問題点3 と同時に片付く）

**どちらでもよい。ただし新しい順にしてから返信バッジを1回押して、正本に着地することを見てから「直した」と書くこと。**

### 2. 【重要】スレッドモードでは「反映済み ✓」が出ない。件数表示も合わない

同じ下書きを仕込んで、モードを切り替えて数えた。

```
フラット: カード 16枚 / .reflected-badge 1個 / 件数表示「16 件（うち下書き 2 件）」
スレッド: カード 15枚 / .reflected-badge 0個 / 件数表示「16 件（うち下書き 2 件）」
```

`renderThreaded()` の `visited` は `entry.id` で重複を弾くので、**同じ id の下書きが1枚まるごと落ちる**（先に来た正本が勝つ）。落ちること自体は「重複を見せない」という意味では悪くない。問題は2つ。

- **落ちるのが「反映済みバッジの付いたカード」なので、機能そのものがモードごと消える。** フラットでは「反映済み ✓」と教えてくれたアプリが、スレッドでは黙る。
- **件数は `render()` の中で `sorted` から計算しているのでモード分岐の前にある。** スレッドで「16 件」と書いてあるのに 15枚しかない。数えれば分かる嘘を画面に出している。

件数はモードで実際に描いた枚数から出すか、少なくとも重複を除いた数にすること。

### 3. 反映済みと分かっているのに、下書きカードは重複表示されたまま

`RF_COUNT = 16 件（うち下書き 2 件）`。**うち1件は、すぐ隣の正本とまったく同じエントリだ。** アプリは「これは反映済みだ」と判定できている。判定できているのに、何もしない。

このアプリには既に「非表示にする」がある（Decision #7 で、削除ではなく非表示という形も決めてある）。**判定した次の行動まで繋げていないだけだ。** 案:

- 反映済みバッジの隣に「下書きを片付ける」ボタンを置く（`hideLocalEntry()` を呼ぶだけ）
- または反映済みの下書きは既定で畳み、「反映済みの下書き 1 件」の一行に集約する

「アプリが状況を説明する」を今日のテーマにしたのなら、**説明の次は片付けの提案**だと思う。
